🔷 DRY Principle (Don't Repeat Yourself)

The DRY Principle states:

"Every piece of knowledge or logic should have a single, authoritative source in the system."

Simply put:

  • 👉 Don't write the same code multiple times.
  • 👉 Write it once and reuse it.

❌ Example 1 (Violates DRY)

Java 
class UserService {

   void createUser(String email) {
       if (!email.contains("@")) {
           throw new IllegalArgumentException("Invalid Email");
       }
   }

   void updateUser(String email) {
       if (!email.contains("@")) {
           throw new IllegalArgumentException("Invalid Email");
       }
   }
}

Problem:

  • The email validation logic is repeated in multiple places.
  • If validation rules change, you must update every copy.

✅ Example 1 (Follows DRY)

Java 
class ValidationUtil {

   static void validateEmail(String email) {
       if (!email.contains("@")) {
           throw new IllegalArgumentException("Invalid Email");
       }
   }
}

class UserService {

   void createUser(String email) {
       ValidationUtil.validateEmail(email);
   }

   void updateUser(String email) {
       ValidationUtil.validateEmail(email);
   }
}

Now the validation logic exists in one place only.

🧠 Real-World Example

Imagine an e-commerce application.

❌ Bad Usage:

orderTotal = price + (price * 0.18);

written in:

  • OrderService
  • InvoiceService
  • CheckoutService

If GST changes from 18% to 20%, you must update it everywhere.

✅ Better:

Java 
class TaxCalculator {

   static double calculateTax(double price) {
       return price * 0.18;
   }
}

Use it everywhere.

So don't Copy-Pasting Business Rules as like this.

💡 Easy Memory Trick

Whenever you copy-paste code, ask:

"If this logic changes tomorrow, how many places must I update?"

  • 1 place → Good ✅
  • 5 places → DRY violation ❌

🎯 Benefits of DRY

  • 1. Easier Maintenance
    Change code in one place.
  • 2. Fewer Bugs
    No risk of forgetting one duplicated copy.
  • 3. Better Readability
    Cleaner and shorter code.
  • 4. More Reusable
    Logic can be shared across the application. ( Reuse existing logic )
  • 5. Faster Development
    Avoid rewriting code

⚠️ Common Mistake

DRY doesn't mean:

"Put everything into one giant method."

It means:

"Avoid duplicating knowledge and logic."

Sometimes a little duplication is better than creating overly complex abstractions.

Example of common mistakes:

In the context of DRY, a common mistake is over-applying DRY.
People see similar code and immediately try to combine it, even when the code has different responsibilities.

❌ Bad Example (Over-DRY)

Java 
void process(String type) {
   if(type.equals("ORDER")) {
       // order logic
   } else if(type.equals("PAYMENT")) {
       // payment logic
   } else if(type.equals("USER")) {
       // user logic
   }
}

Here, different business operations are forced into one method just to avoid duplication. The code becomes harder to understand and maintain.

✅ Better Approach

Java 
class OrderService {
   void processOrder() { }
}

class PaymentService {
   void processPayment() { }
}

class UserService {
   void processUser() { }
}

Each class has a clear responsibility.

So Understand:

A common DRY mistake is over-abstraction—combining unrelated code just to remove duplication.

DRY should eliminate duplicated knowledge and business logic, not sacrifice readability or good design.

🎤 Summary

DRY (Don't Repeat Yourself) is a software design principle that avoids duplication of logic, rules, and knowledge by keeping each piece of functionality in a single, reusable location.
