Dependency Inversion Principle

DIP - Fifth Principle of SOLID

Home / LLD / Dependency Inversion Principle

DIP is the fifth principle of SOLID.

It says that high-level modules should not depend on low-level modules. Both should depend on abstractions.

🔷 Dependency Inversion Principle (DIP)

It states:

High-level modules should not depend on low-level modules. Both should depend on abstractions.

Abstractions should not depend on details. Details should depend on abstractions.

🧠 Simple Meaning

Instead of this direct dependency:

Concept 
CheckoutService → StripePayment

use:

CheckoutService → PaymentGateway ← StripePayment

So the high-level business logic depends on an PaymentGateway interface, not a concrete implementation.

❌ Example 1 (Violates DIP)

Java 
class StripePayment {
    public void pay(double amount) {
        System.out.println("Paid using Stripe: " + amount);
    }
}

class CheckoutService {
    private StripePayment payment = new StripePayment();

    public void checkout(double amount) {
        payment.pay(amount);
    }
}

Problem

CheckoutService directly depends on StripePayment.

If tomorrow you want RazorpayPayment, you must modify CheckoutService.

❌ Tight coupling

✅ Example 1 (Follows DIP)

Abstraction

Java 
interface PaymentGateway {
    void pay(double amount);
}

Low-Level Modules

Java 
class StripePayment implements PaymentGateway {
    public void pay(double amount) {
        System.out.println("Paid using Stripe: " + amount);
    }
}

class RazorpayPayment implements PaymentGateway {
    public void pay(double amount) {
        System.out.println("Paid using Razorpay: " + amount);
    }
}

High-Level Module

Java 
class CheckoutService {
    private PaymentGateway paymentGateway;

    public CheckoutService(PaymentGateway paymentGateway) {
        this.paymentGateway = paymentGateway;
    }

    public void checkout(double amount) {
        paymentGateway.pay(amount);
    }
}

Main

Java 
public class Main {
    public static void main(String[] args) {
        PaymentGateway gateway = new StripePayment();
        CheckoutService service = new CheckoutService(gateway);
        service.checkout(1000);
    }
}

🎯 Why DIP Is Important

Without DIP

CheckoutService → StripePayment

If Stripe changes, CheckoutService may change.

With DIP

CheckoutService → PaymentGateway

PaymentGateway ← StripePayment, RazorpayPayment, PayPalPayment

New payment providers can be added without touching CheckoutService.

🧠 Relationship with Dependency Injection

DIP

Dependency Inversion Principle is a design principle.

It says: depend on abstractions.

Dependency Injection (DI)

Dependency Injection is a technique to implement DIP. 

OrderService(Notification notification)

The dependency is injected from outside instead of being created inside the class.
