🧠 Interview Tips — System Design

A single, numbered checklist you can scan quickly during interviews.

Core mindset & requirements

  1. Understand the functional and non-functional requirements before designing.
  2. Clearly define the use cases and constraints of the system.
  3. There is no perfect solution. It's all about tradeoffs.
  4. Assume everything can and will fail. Make it fault tolerant.
  5. Keep it simple. Avoid over-engineering.

Scalability & performance

  1. Design your system for scalability from the ground up.
  2. Prefer horizontal scaling over vertical scaling for scalability.
  3. Use Load Balancers to ensure high availability and distribute traffic.
  4. Use CDNs to reduce latency for a global user base.
  5. Use edge computing to process data closer to users.
  6. Use caching to reduce load on the database and improve response times.
  7. Use write-through cache for write-heavy applications.
  8. Use read-through cache for read-heavy applications.
  9. Use Time-To-Live (TTL) values to automatically expire cached data and reduce staleness.
  10. Pre-populate critical data in the cache to avoid cold starts.
  11. Implement Autoscaling to handle traffic spikes smoothly.
  12. Plan capacity forecasting based on growth trends.
  13. Implement data compression to reduce network bandwidth usage.
  14. Use content delivery optimization like image resizing and lazy loading.

Databases & data

  1. Consider using SQL Databases for structured data and ACID transactions.
  2. Opt for NoSQL Databases when dealing with unstructured data.
  3. Consider using a graph database for highly connected data.
  4. Use Database Sharding to scale SQL databases horizontally.
  5. Use Database Indexing to optimize the read queries in databases.
  6. Assume everything can and will fail. Make it fault tolerant.
  7. Implement data partitioning and sharding for large datasets.
  8. Consider denormalizing databases for read-heavy workloads.
  9. Use bloom filters to check for an item in a large dataset quickly.
  10. Implement Data Replication and Redundancy to avoid single point of failure.
  11. Avoid hotspots by distributing traffic evenly across partitions.
  12. Use consistent hashing for scalable data partitioning.
  13. Consider using a data lake or data warehouse for analytics and reporting.
  14. Use object storage like S3 for storing large datasets and media files.

APIs, services & communication

  1. Use Rate Limiting to prevent system from overload and DOS attacks.
  2. Use API Gateways to manage authentication, routing, and rate limiting.
  3. Implement Service Discovery so services can dynamically find each other.
  4. Use Health Checks to ensure only healthy servers receive traffic.
  5. Consider using WebSockets for real-time communication.
  6. Use Heartbeat Mechanisms to detect failures.
  7. Consider using a message queue for asynchronous communication.
  8. Use Dead Letter Queues to handle failed messages safely.
  9. Use Asynchronous processing for background tasks.
  10. Use batch processing for non-urgent tasks to optimize resources.
  11. Implement Backpressure mechanisms to protect systems during overload.
  12. Use Distributed Locks to coordinate operations across multiple services.
  13. Use Event-Driven Architecture for loosely coupled systems.
  14. Use Schema Versioning to maintain backward compatibility in APIs.
  15. Use Pagination to efficiently handle large datasets in APIs.

Reliability patterns

  1. Implement comprehensive logging and monitoring to track the system's performance and health.
  2. Maintain observability using metrics, logs, and distributed tracing.
  3. Implement circuit breakers to prevent a single failing service from bringing down the entire system.
  4. Use Bulkhead Pattern to isolate failures between system components.
  5. Apply Retry mechanisms with exponential backoff for transient failures.
  6. Make operations idempotent to simplify retry logic and error handling.
  7. Design idempotent APIs so repeated requests don't cause duplicate effects.
  8. Implement request deduplication to avoid duplicate processing.
  9. Implement chaos engineering practices to test system resilience and find vulnerabilities.
  10. Design for statelessness when possible to improve scalability and simplify architecture.
  11. Design systems to handle eventual consistency in distributed environments.
  12. Use leader election algorithms when coordination between nodes is required.
  13. Use failover mechanisms to automatically switch to a redundant system when a failure is detected.
  14. Distribute your system across different data centers to prevent localized failures.
  15. Design graceful degradation when parts of the system fail.

Security & delivery

  1. Implement security best practices such as authentication and authorization.
  2. Encrypt sensitive data at rest and in transit.
  3. Use token-based authentication (JWT, OAuth) for secure API access.
  4. Implement audit logs to track important system activities.
  5. Use feature flags to release features safely without redeployment.
  6. Apply blue-green deployment or canary releases for safer deployments.
  7. Always design for maintainability and operability.
