🔷 Flyweight Design Pattern

The Flyweight Pattern is a Structural Design Pattern.

🪶

Definition

Separate an abstraction from its implementation so that both can vary independently

In Detailed terms:

The Flyweight pattern is a structural design pattern that minimizes memory usage by sharing common state across a large number of similar objects instead of storing that state in each object individually.

Two characteristics define the Flyweight pattern and set it apart from other structural patterns:

🔄

Intrinsic / Extrinsic State

Intrinsic/extrinsic state separation: The pattern divides object state into two parts. Intrinsic state is shared and immutable, stored inside the flyweight. Extrinsic state is context-dependent and unique, stored outside the flyweight and passed in when needed. This separation is what makes sharing possible.

🏭

Factory-Managed Caching

Factory-managed caching: A dedicated factory object controls the creation and reuse of flyweights. Clients never instantiate flyweights directly. They go through the factory, which maintains a cache and ensures that identical flyweights are shared rather than duplicated.

Problem

Imagine a game with:

  • 1000 Trees

Every tree has:

Tree
├── Image
├── Color
├── X Position
└── Y Position

A beginner creates 1000 Tree objects, each storing the same image and color.

Results in Huge memory waste.

Bad code: (Beginners Code)

Tree Class

Tree.java 
class Tree {

   private String image;
   private String color;
   private int x;
   private int y;

   public Tree(String image, String color, int x, int y) {
       this.image = image;
       this.color = color;
       this.x = x;
       this.y = y;
   }

   public void display() {
       System.out.println( image + " " + color + " (" + x +  "," + y + ")" );
   }
}

Client

Main.java 
public class Main {
   public static void main(String[] args) {
       Tree t1 = new Tree( "Tree.png", "Green",10,  20 );
       Tree t2 = new Tree("Tree.png","Green",30,40 );
       Tree t3 = new Tree( "Tree.png", "Green",50,60 );
   }
}

🚨 Issues

Every object stores:

  • Image
  • Color

again and again.

For: 1000 Trees
Huge duplication.

🎯 What's Common?

Every tree has: Image, Color

These never change.

These are called: Intrinsic State

What's Different?

Each tree has: X Position, Y Position

These are unique.

So they Called: Extrinsic State

Flyweight solution

// Flyweight

TreeType.java 
// Flyweight
interface TreeType {
    void display(int x, int y);
}

The flyweight interface declares a single method, display(x, y), where x and y represent extrinsic state. The flyweight itself does not store position. Instead, the caller passes position in at render time.

// Concrete Flyweight

ConcreteTreeType.java 
// Concrete Flyweight
class ConcreteTreeType implements TreeType {

    private final String image;
    private final String color;

    public ConcreteTreeType(String image, String color) {
        this.image = image;
        this.color = color;
    }

    @Override
    public void display(int x, int y) {
        System.out.println( image + " " + color + " (" + x + ", " + y + ")" );
    }
}

The concrete flyweight stores intrinsic state only. The display() method combines the stored intrinsic state with the extrinsic position parameters to render the character.

// Flyweight Factory

TreeFactory.java 
// Flyweight Factory
import java.util.HashMap;
import java.util.Map;

class TreeFactory {

    private final Map<String, TreeType> treeTypes = new HashMap<>();

    public TreeType getTreeType( String image, String color) {
        String key = image + "_" + color;
        treeTypes.putIfAbsent( key, new ConcreteTreeType(image, color) );
        return treeTypes.get(key);
    }

    public int getTreeTypeCount() {
        return treeTypes.size();
    }
}

Maintains a Map: It maintains a map of already-created flyweights, keyed by a string that concatenates all intrinsic fields.

Checks the Cache First: When a client requests a flyweight, the factory checks the map first.

If Already Exists: If a matching flyweight exists, it returns the cached instance.

If Not Found: If not, it creates a new one, stores it, and returns it.

Guarantee: This guarantees that identical combinations of intrinsic state are never duplicated.

// Context (Extrinsic State)

Tree.java 
// Context (Extrinsic State)
class Tree {

    private final TreeType treeType;
    private final int x;
    private final int y;

    public Tree( TreeType treeType, int x, int y) {
        this.treeType = treeType;
        this.x = x;
        this.y = y;
    }

    public void display() {
        treeType.display(x, y);
    }
}

// Client

Main.java 
// Client
public class Main {
    public static void main(String[] args) {

        TreeFactory factory = new TreeFactory();

        Tree t1 = new Tree(factory.getTreeType("Tree.png", "Green"), 10,20 );
        Tree t2 = new Tree( factory.getTreeType("Tree.png", "Green"), 30, 40 );
        Tree t3 = new Tree( factory.getTreeType("Tree.png", "Green"), 50, 60 );

        t1.display();
        t2.display();
        t3.display();

        System.out.println(  "\nUnique Tree Types : " + factory.getTreeTypeCount() );
    }
}

Output

Tree.png Green (10, 20)
Tree.png Green (30, 40)
Tree.png Green (50, 60)

Unique Tree Types : 1

Explanation

HOW IT WORKS

  • Client requests a tree with (image, color).
  • Factory checks if that combination already exists.
  • If yes, return the existing TreeType (shared).
  • Client creates a new Tree with its own X, Y.
  • All trees share the same TreeType object.

When To Use

✅ Use Flyweight when:

  • Huge number of similar objects.
  • Memory usage is high.
  • Many objects share common state.

❌ Don't use Flyweight when:

  • Few objects exist.
  • Objects don't share common data.
  • Memory isn't a concern.

Adding Flyweight would make the design unnecessarily complex.

🎯 Summary

Flyweight Pattern is a Structural Design Pattern that minimizes memory usage by sharing common, immutable data (intrinsic state) among many objects while keeping unique data (extrinsic state) separate.

Instead of creating duplicate objects containing the same information, Flyweight stores shared state once and reuses it across multiple objects.

It is commonly used in game engines, text editors, browsers, icon libraries, and rendering systems where thousands or millions of similar objects exist.
