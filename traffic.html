📊 Traffic: Understanding Request Volume

1️⃣ What is Traffic?

Traffic refers to the number of requests sent by users to your application over time.

In simple words:

Traffic = how many users are hitting your system and how often

Examples:

  • 👥 10 users opening a website → low traffic
  • 🛍️ 1 million users shopping during a sale → high traffic

2️⃣ Why Does Traffic Exist?

Traffic exists because:

  • 👤 Users interact with applications
  • 📨 Apps receive requests for data, actions, or services

Traffic becomes a problem when:

  • ⚠️ Requests exceed system capacity
  • ⚠️ Servers cannot process requests fast enough

👉 System design is mainly about handling traffic efficiently.

3️⃣ What Breaks When Traffic Increases?

If traffic increases and the system is not designed properly:

  • ⚠️ Server overload
  • 🐌 Slow response times
  • ❌ Timeouts and errors (5xx)
  • 💥 Database crashes
  • 🔴 Complete system downtime

📌 Real-World Example:

A ticket booking site crashes the moment sales open due to unexpected traffic surge → millions in lost revenue ❌

4️⃣ Types of Traffic

🔹 Low Traffic

  • Few users
  • Single server can handle it
  • Simple architecture

📈 High Traffic

  • Many users simultaneously
  • Needs scaling
  • Load balancers & caching

📖 Read Traffic

  • Users fetching data
  • Example: browsing products
  • Usually much higher volume

✏️ Write Traffic

  • Users modifying data
  • Example: placing orders
  • Smaller volume but critical

📌 Key Insight: Read traffic is usually much higher than write traffic.

5️⃣ Traffic Patterns

🔁 Steady Traffic

Constant load with predictable patterns. Example: internal tools, HR systems.

⚡ Spike Traffic

Sudden surge in requests. Example: sales, exam results, product launches.

🌍 Global Traffic

Users from multiple regions hitting servers simultaneously. Requires CDN & distributed systems.

⏰ Peak-Hour Traffic

Specific time windows with high load. Example: evenings, sales, business hours.

6️⃣ How Systems Handle Traffic (Core Techniques)

⚖️ Load Balancer

Distributes traffic across servers to prevent overload.

🧊 Cache

Reduces repeated requests to database for faster responses.

🌍 CDN

Handles static content closer to users reducing origin load.

📈 Scaling

Horizontal: add more servers. Vertical: increase server power.

⏳ Rate Limiting

Controls excessive traffic to prevent abuse and maintain system stability.

7️⃣ Why Not Allow Unlimited Traffic?

Because:

  • ⚙️ Servers have limits on CPU, memory, network bandwidth
  • 💰 Databases are expensive to scale infinitely
  • 💥 Unlimited traffic can crash systems and cause cascade failures
  • 🚨 Can be exploited by attackers (DDoS attacks)

👉 Systems must control traffic, not just accept it.

8️⃣ If Traffic Is Too Much, What Else Can We Do?

Problem Solution
Sudden spikes Queue requests, auto-scaling
Heavy reads Cache layer, read replicas
Global users CDN, edge servers
Too many writes Sharding, message queues
Abuse & DDoS Rate limiting, WAF
Expensive DB hits Pre-computed data, materialized views

9️⃣ Traffic in Real Apps

🛒 E-commerce App

  • 👁️ Browsing: High read traffic
  • ✏️ Checkout: Low but critical write traffic
  • 📦 Inventory: Constant updates during sales

💬 Chat Application

  • 💬 Messages: Continuous traffic
  • ⌨️ Typing status: High but lightweight traffic
  • 🔔 Notifications: Spike during peak hours

🎬 Streaming App

  • 📋 Metadata: API traffic
  • 🎥 Video content: CDN traffic
  • 📊 Analytics: Background batch traffic

🧠 Summary

Traffic refers to the volume and pattern of requests hitting a system, and system design focuses on handling this traffic efficiently without performance degradation or failures.

💡 Pro Tip

Always design your system for 3-5x the expected traffic. This provides headroom for growth and unexpected spikes without immediate system failures.

Monitor traffic metrics: Requests per second (RPS), latency, error rates, and bandwidth usage to identify bottlenecks early.
