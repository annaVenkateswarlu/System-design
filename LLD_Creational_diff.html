🚀 Creational Design Patterns

The purpose of all Creational Design Patterns is : To control and simplify object creation.

But each pattern solves a different problem.

🚀 Creational Design Patterns - Quick Comparison

Pattern Purpose Creates How? Best Use Case
Singleton Ensure only one object exists Reuses the same instance Logger, Config Manager, Cache Manager
Factory Hide object creation logic Creates one object based on input Payment Gateway, Notification Service
Builder Construct complex objects step-by-step Builds object incrementally User, Employee, House with many optional fields
Prototype Create objects by copying existing objects Cloning Expensive object creation, Templates
Abstract Factory Create families of related objects Factory creates multiple related objects UI Components, Furniture Families

1️⃣ Singleton S

Problem

Multiple objects are being created unnecessarily.

Logger logger1 = new Logger();
Logger logger2 = new Logger();
Logger logger3 = new Logger();
Solution

Allow only one object in the entire application.

Logger logger = Logger.getInstance();
Real World Example
  • Logger
  • Configuration Manager
  • Cache Manager

2️⃣ Factory Pattern F

Problem

Client doesn't know which implementation to create.

if(type.equals("UPI"))
    return new UpiPayment();

if(type.equals("CARD"))
    return new CardPayment();
Solution

Factory decides which object to create.

Payment payment = PaymentFactory.getPayment(type);
Real World Example
  • Payment Methods
  • Notification Systems
  • Vehicle Creation

3️⃣ Builder Pattern B

Problem

Object has many parameters and constructors become messy.

Student student = new Student(
    "Anna",
    22,
    "CSE",
    "A",
    "Hyderabad",
    "9876543210"
);
Solution

Build object step-by-step.

Student student =
    new Student.Builder()
        .name("Anna")
        .age(22)
        .branch("CSE")
        .build();
Real World Example
  • Student
  • Employee
  • HTTP Request

4️⃣ Prototype Pattern P

Problem

Creating objects is expensive or repetitive.

Soldier soldier = new Soldier();

// Creating thousands of soldiers is slow.
Solution

Clone an existing object.

Soldier copy = original.clone();
Real World Example
  • Game Characters
  • PowerPoint Duplicate Slide
  • Figma Duplicate Frame
  • Document Templates

5️⃣ Abstract Factory Pattern AF

Problem

Need to create multiple related objects together.

WindowsButton
WindowsCheckbox

or

MacButton
MacCheckbox

Need them together.
Solution

Factory creates an entire family of objects.

GUIFactory factory = new WindowsFactory();

Button button = factory.createButton();

Checkbox checkbox = factory.createCheckbox();
Real World Example
  • Windows UI Components
  • Mac UI Components

  • AWS Services
  • Azure Services

  • MySQL Family
  • Oracle Family

🚀 Creational Design Patterns - One-Line Interview Definitions

Pattern Interview Answer
Singleton "I use Singleton when exactly one instance of a class should exist throughout the application and be globally accessible."
Factory Method "I use Factory Method when the client should not decide which concrete object to create and object creation needs to be centralized."
Builder "I use Builder when an object has many fields or optional parameters and needs to be constructed step-by-step."
Prototype "I use Prototype when creating an object is expensive and cloning an existing object is more efficient than creating a new one."
Abstract Factory "I use Abstract Factory when I need to create families of related objects without specifying their concrete classes."
