Problem 5

🗄️ How to Improve Database Performance

👉 Interviewer asks:

How would you improve database performance?

Improving database performance can be approached in two phases: first optimizing the existing system, and then scaling it if needed.

So I would first optimize the database, and if that is not sufficient, then I would move to scaling techniques.

📊 Database Optimization

🎯 Goal of Optimization:

👉 Make queries faster without changing system size

🔵 1. Data Indexing

They act as a data structure that provides a quick way to locate and access data without scanning the entire dataset.

  • 📌 Add indexes on frequently queried columns
  • ✔ Speeds up lookups
  • ✔ Avoids full table scans

🔵 2. Query Optimization

Query optimization means improving a SQL query so it uses less time, less memory, and fewer resources.

  • ✔ Avoid SELECT *
  • ✔ Avoid Nested Queries (Use JOINs)
  • ✔ Use WHERE conditions efficiently

🔵 3. Connection Pooling

Connection pooling is a technique where a set of pre-initialized connections (to a database, API, or other resource) is maintained and reused instead of creating and destroying a connection for every request.

  • ✔ Reuse DB connections
  • ✔ Avoid connection overhead

🔵 4. Denormalization

Denormalization is a database optimization technique where redundant data is intentionally added to one or more tables to reduce the need for complex joins and improve query performance.

  • ✔ Reduce joins by storing computed data
  • ✔ Store computed data

🔵 5. Materialized Views

A materialized view is a stored, precomputed result of a query instead of computing it every time.
Store pre-computed query results for quick access, reducing the need to process complex queries repeatedly.

This improves performance but requires periodic refresh to stay updated.

  • ✔ Store precomputed query results
  • ✔ Faster data retrieval (Faster Reads)

🔵 6. Pagination

Pagination means fetching and displaying data in limited batches (pages) to improve performance and user experience.

  • ✔ Don't fetch large datasets at once
  • ✔ Uses LIMIT and OFFSET

🔵 7. Caching

  • ✔ Cache frequently accessed data
  • ✔ Reduce DB hits

📈 Database Scaling (Infra Change)

🎯 Goal of Scaling:

👉 Handle more users + more data

🔴 1. Vertical Scaling

Increase the capacity of the database server by adding more CPU, RAM, or storage.

  • ✔ Increase CPU / RAM

🔴 2. Read Replicas

Separate reads from writes.

  • ✔ Distribute read traffic
  • ✔ Primary → writes
  • ✔ Replica → reads

🔴 3. Sharding

Divide the database into smaller, manageable pieces, or shards, to distribute load and improve performance.

  • ✔ Split data across multiple DBs
  • ✔ Handles large datasets

🔴 4. Partitioning

Split large tables into smaller, more manageable pieces to improve query performance and maintenance.

  • ✔ Split large tables into smaller parts

🔴 5. Replication

Create copies of the primary database on different servers to distribute read load and enhance availability.

  • ✔ Improve availability + performance

💬 One Line Answer

To improve database performance, I would first focus on optimization techniques such as indexing, query optimization, connection pooling, caching, and denormalization to reduce query latency.

If the system still cannot handle the load, I would move to scaling strategies such as vertical scaling, read replicas for read-heavy workloads, and sharding or partitioning for large datasets.

This ensures both efficient performance and scalability.

🧠 Key Takeaways

  • 👉 Optimization = Make system faster
  • 👉 Scaling = Handle more load

Optimization improves efficiency, while scaling improves capacity.

🧠 Interview Tips

  • Start with optimization — No infrastructure changes needed
  • Show progression — Optimization first, then scaling
  • Discuss trade-offs — Optimization vs Scaling
  • Quantify improvements — "This reduces query time by X%"
  • Know when to scale — When optimization isn't enough
