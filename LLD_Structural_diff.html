🧩 Structural Design Patterns

The purpose of all Structural Design Patterns is :

To organize classes and objects into larger structures while keeping them flexible and efficient.

🔥 Structural Design Patterns - Differences (Problem & Solution)

Pattern Problem Solution
Adapter Two classes have incompatible interfaces and cannot work together directly. Converts one interface into another expected by the client, allowing incompatible classes to collaborate.
Decorator Need to add new features to an object dynamically without creating many subclasses or modifying existing code. Wraps the original object with decorator objects that add new behavior while keeping the same interface.
Facade A subsystem contains many classes and interactions, making it difficult for clients to use. Provides a single simplified interface that hides the complexity of the underlying subsystem.
Proxy Direct access to an object needs to be controlled for security, logging, caching, lazy loading, or remote access. Places a proxy object in front of the real object to control access before forwarding requests.
Composite Individual objects and groups of objects (tree structures) must be handled differently, making client code complex. Provides a common interface so clients can treat both single objects and groups uniformly.
Bridge Two independent dimensions (e.g., Remote × TV) lead to a large number of subclasses due to combinations. Separates abstraction from implementation so both hierarchies can evolve independently without class explosion.
Flyweight A huge number of similar objects consume excessive memory because they store duplicate data. Shares common (intrinsic) state between objects while keeping only unique (extrinsic) state in each object.

📚 Structural Design Patterns - What Is It & When To Use

Pattern What Is It? When To Use
Adapter A pattern that converts the interface of an existing class into another interface expected by the client. When integrating third-party libraries, legacy systems, or external APIs whose interfaces don't match your application's interface.
Decorator A pattern that dynamically adds new behavior or responsibilities to an object by wrapping it. When features need to be added dynamically at runtime without modifying existing classes or creating many subclasses.
Facade A pattern that provides a single, simplified interface to a complex subsystem. When a subsystem has many classes and clients should interact through one simple entry point.
Proxy A pattern that provides a representative object to control access to another object. When access to an object needs authentication, authorization, caching, logging, lazy loading, or remote communication.
Composite A pattern that organizes objects into tree structures and lets clients treat individual and grouped objects uniformly. When modeling hierarchical structures such as file systems, organization charts, menus, or UI component trees.
Bridge A pattern that separates abstraction from implementation so they can change independently. When a class has multiple independent dimensions of variation and inheritance would create too many subclasses.
Flyweight A pattern that shares common object state among many objects to reduce memory usage. When an application creates a very large number of similar objects that share common data and memory optimization is important.

🎯 One-Line Difference Between All Structural Patterns

Pattern One-Line Purpose
Adapter Makes incompatible interfaces work together.
( Translator )
Decorator Adds new functionality to an object dynamically.
( Feature Adder )
Facade Hides the complexity of a subsystem behind a simple interface.
( Receptionist )
Proxy Controls or manages access to an object.
( Security Guard )
Composite Treats individual objects and groups of objects in the same way.
( Tree Builder )
Bridge Separates abstraction and implementation to avoid class explosion.
( Class Explosion Preventer )
Flyweight Shares common object data to reduce memory usage.
( Memory Saver )
