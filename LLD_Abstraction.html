🎭 Abstraction

🎭 What is Abstraction?

Abstraction means:

  • Hiding implementation details
  • Showing only essential features

In simple words: "User should know what to do, not how it works inside"

Abstraction = Hiding Complexity + Showing Essentials

Abstraction focuses on hiding complexity. It's about simplifying what the user sees.
Encapsulation focuses on hiding data. It's about bundling data and methods together to protect an object's internal state.

🧠 Real-Life Analogy

Think of driving a car 🚗

  • You press accelerator → car moves
  • You don't know how engine works internally

👉 That's abstraction:

  • What you see = simple
  • What happens inside = hidden

💡 Why Abstraction is Important in LLD

1. Reduces Complexity

User sees only what is needed

2. Improves Flexibility

You can change internal logic anytime

3. Encourages Loose Coupling

Works perfectly with interfaces

🔍 Abstraction vs Encapsulation

Abstraction focuses on hiding complexity. It's about simplifying what the user sees.
Encapsulation focuses on hiding data. It's about bundling data and methods together to protect an object's internal state.

Aspect Encapsulation Abstraction
Focus Protecting data inside a class Hiding complexity from the user
Goal Restrict direct access to internal state Show only necessary features
Level Implementation-level Design-level
What it hides Data (variables) Logic/implementation details
How it is achieved Using private, getters/setters Using interface, abstract class
User visibility Controls how data is accessed Controls what user can see/use
Example private balance in BankAccount Only deposit() and withdraw() exposed

Abstraction is the external view of an object, while Encapsulation is the internal view.

🛠️ How Abstraction Is Achieved

In object-oriented programming, abstraction is primarily achieved through three mechanisms: abstract classes, interfaces, and clean public APIs. Each serves a different purpose and fits different situations.

🔷 1. Abstraction using Interface (Pure Abstraction)

👉 Use when:

  • You only want to define a contract
  • No shared implementation

💡 Example: Payment System

Step 1: Define Interface

Java 
interface Payment {
   void pay(double amount);
}

Step 2: Implement Different Payments

Java 
class UpiPayment implements Payment {
   public void pay(double amount) {
       System.out.println("Paid " + amount + " using UPI");
   }
}

class CreditCardPayment implements Payment {
   public void pay(double amount) {
       System.out.println("Paid " + amount + " using Credit Card");
   }
}

Step 3: Use It

Java 
public class Main {
   public static void main(String[] args) {
       Payment payment = new UpiPayment();
       payment.pay(500);

       payment = new CreditCardPayment();
       payment.pay(1000);
   }
}

What Abstraction Achieved Here

  • User just calls: pay()
  • Doesn't care HOW payment happens
  • Easily extendable → add WalletPayment, CryptoPayment

👉 This is PURE abstraction (no shared logic)

🔶 2. Abstraction using Abstract Class (Partial Abstraction)

👉 Use when:

  • You want common code + some abstraction

💡 Example: Vehicle System

Step 1: Abstract Class

Java 
abstract class Vehicle {
   
   // Abstract method (must be implemented)
   abstract void start();

   // Concrete method (common logic)
   void fuelType() {
       System.out.println("Uses fuel");
   }
}

Step 2: Implement Child Classes

Java 
class Car extends Vehicle {
   void start() {
       System.out.println("Car starts with key");
   }
}

class Bike extends Vehicle {
   void start() {
       System.out.println("Bike starts with self-start");
   }
}

Step 3: Use It

Java 
public class Main {
   public static void main(String[] args) {
       Vehicle v = new Car();
       v.start();
       v.fuelType();

       v = new Bike();
       v.start();
   }
}

What Abstraction Achieved Here

  • start() → different behavior (hidden implementation)
  • fuelType() → shared logic reused
  • Code reuse + abstraction together

👉 This is PARTIAL abstraction

🔥 Key Difference

Feature Interface Abstract Class
Abstraction Full abstraction Partial Abstraction
Methods Mostly abstract Both abstract + concrete
Code reuse ❌ No ✅ Yes
Use case Contract Base class with shared logic

🧠 When to Use What?

👉 Use Interface when:

  • Multiple implementations needed
  • No shared logic
  • Example: Payment, Notification

👉 Use Abstract Class when:

  • Some common behavior exists
  • Example: Vehicle, Shape

📻 Practical Example: Media Player

Imagine you're building a media application that needs to play different types of content: audio files, video files, and streaming content.
Each type has a completely different playback mechanism, but they all share certain behaviors: displaying the current status and logging user actions.

Figure 1: MediaPlayer abstract class with concrete and abstract methods

The abstract MediaPlayer defines three abstract methods (play(), pause(), stop()) that each subclass must implement, plus two concrete methods (displayStatus() and logAction()) that all players inherit.
The PlayerController depends only on the abstract MediaPlayer, so it works with any player type without modification.

Java 
abstract class MediaPlayer {
    protected String playerName;

    public MediaPlayer(String playerName) {
        this.playerName = playerName;
    }

    // Abstract methods: each player type implements these differently
    abstract void play();
    abstract void pause();
    abstract void stop();

    // Concrete methods: shared behavior inherited by all players
    void displayStatus() {
        System.out.println("[" + playerName + "] Status: Ready");
    }

    void logAction(String action) {
        System.out.println("[" + playerName + "] Action: " + action);
    }
}


class AudioPlayer extends MediaPlayer {
    private String audioFile;

    public AudioPlayer(String audioFile) {
        super("AudioPlayer");
        this.audioFile = audioFile;
    }

    @Override
    void play() {
        logAction("Playing audio: " + audioFile);
    }

    @Override
    void pause() {
        logAction("Paused audio: " + audioFile);
    }

    @Override
    void stop() {
        logAction("Stopped audio: " + audioFile);
    }
}


class VideoPlayer extends MediaPlayer {
    private String videoFile;
    private String resolution;

    public VideoPlayer(String videoFile, String resolution) {
        super("VideoPlayer");
        this.videoFile = videoFile;
        this.resolution = resolution;
    }

    @Override
    void play() {
        logAction("Playing video: " + videoFile + " at " + resolution);
    }

    @Override
    void pause() {
        logAction("Paused video: " + videoFile);
    }

    @Override
    void stop() {
        logAction("Stopped video: " + videoFile);
    }
}


class StreamingPlayer extends MediaPlayer {
    private String streamUrl;
    private int bufferSize;

    public StreamingPlayer(String streamUrl, int bufferSize) {
        super("StreamingPlayer");
        this.streamUrl = streamUrl;
        this.bufferSize = bufferSize;
    }

    @Override
    void play() {
        logAction("Streaming from: " + streamUrl + " (buffer: " + bufferSize + "KB)");
    }

    @Override
    void pause() {
        logAction("Paused stream: " + streamUrl);
    }

    @Override
    void stop() {
        logAction("Stopped stream: " + streamUrl);
    }
}


class PlayerController {
    private MediaPlayer player;

    public PlayerController(MediaPlayer player) {
        this.player = player;
    }

    void startPlayback() {
        player.displayStatus();
        player.play();
    }

    void pausePlayback() {
        player.pause();
    }

    void stopPlayback() {
        player.stop();
    }
}


public class Main {
    public static void main(String[] args) {
        PlayerController audioCtrl = new PlayerController(
            new AudioPlayer("song.mp3"));
        audioCtrl.startPlayback();
        audioCtrl.pausePlayback();

        System.out.println();

        PlayerController videoCtrl = new PlayerController(
            new VideoPlayer("movie.mp4", "1080p"));
        videoCtrl.startPlayback();
        videoCtrl.stopPlayback();

        System.out.println();

        PlayerController streamCtrl = new PlayerController(
            new StreamingPlayer("https://stream.example.com/live", 2048));
        streamCtrl.startPlayback();
        streamCtrl.stopPlayback();
    }
}

📝 Key Takeaways

  • Abstraction = Hide complexity, show essentials
  • Interface = Pure abstraction (contract only)
  • Abstract Class = Partial abstraction (code reuse + abstraction)
  • Use Interface = No shared logic, multiple implementations
  • Use Abstract Class = Common behavior exists
  • Encapsulation ≠ Abstraction (internal vs external view)
