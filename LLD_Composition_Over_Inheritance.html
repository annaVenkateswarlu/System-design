🔷 Composition Over Inheritance Principle (Composing Objects Principle)

The principle says:

"Favor object composition over class inheritance."

In simple words:

👉 Instead of inheriting behavior from a parent class, compose objects by combining smaller, reusable components.

❌ Using Inheritance

Suppose we have a car that uses a petrol engine.

Java 
class PetrolEngine {
   public void start() {
       System.out.println("Petrol Engine started");
   }
}

class Car extends PetrolEngine {
   public void drive() {
       start();
       System.out.println("Car is moving");
   }
}

public class Main {
   public static void main(String[] args) {
       Car car = new Car();
       car.drive();
   }
}

Problem

Tomorrow if you want an Electric Engine:
class ElectricEngine { ... }

You cannot easily switch engines because Car is tightly bound to PetrolEngine.

✅ Using Composition

Java 
interface Engine {
   void start();
}

class PetrolEngine implements Engine {
   public void start() {
       System.out.println("Petrol Engine started");
   }
}

class ElectricEngine implements Engine {
   public void start() {
       System.out.println("Electric Engine started");
   }
}

class Car {
   private Engine engine;

   public Car(Engine engine) {
       this.engine = engine;
   }

   public void drive() {
       engine.start();
       System.out.println("Car is moving");
   }
}

public class Main {
   public static void main(String[] args) {

       Car petrolCar = new Car(new PetrolEngine());
       petrolCar.drive();

       Car electricCar = new Car(new ElectricEngine());
       electricCar.drive();
   }
}

Output

Petrol Engine started

Car is moving

Electric Engine started

Car is moving

🎯 Why Composition is Better

1.Flexibility

Change behavior without changing Car.
Car car = new Car(new ElectricEngine());

2. Reusability

The same engine can be used by : Car , Truck , Bike

3. Low Coupling

Car depends on the Engine interface, not a specific engine.

4. Easier Maintenance

Adding a new engine:
class HybridEngine implements Engine
No changes to Car.

🧠 Real-World Example

Inheritance ❌

Car IS-A PetrolEngine
This doesn't make sense.

Composition ✅

Car HAS-A Engine
This matches the real world.

💡 Easy Memory Trick

Whenever you're about to use inheritance, ask:

Can I honestly say "Child IS-A Parent"?

If YES → inheritance may be appropriate.
If NO → use composition.

🎯 Summary

Composition Over Inheritance is a design principle that recommends building classes using object composition (HAS-A relationships) rather than class inheritance (IS-A relationships), resulting in more flexible, maintainable, and loosely coupled systems.
