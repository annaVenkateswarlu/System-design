1️⃣ What is it?

Security in system design is about protecting data, services, and users from unauthorized access, attacks, and misuse.

🎯 Goal: CIA Triad

Confidentiality + Integrity + Availability

✅ Security ensures:

  • Only authorized users access data
  • Data is not altered
  • Systems stay available

2️⃣ Real-world Analogy

🏦 Bank Security

  • ID check → Authentication
  • Access level → Authorization
  • CCTV → Monitoring
  • Vault lock → Encryption

3️⃣ Core Security Concepts

🔹 1. Authentication (Who are you?)

Verify user identity.

📝 Examples:

  • Username + password
  • OTP
  • Biometrics

🔧 Common methods:

  • OAuth 2.0
  • JWT

👉 "Is this user real?"

🔹 2. Authorization (What can you do?)

After login, decide permissions.

Authorization determines what actions an authenticated user can perform

📝 Examples:

  • Admin vs user
  • Read vs write

🔧 Models:

  • RBAC (Role-based access)
  • ABAC (Attribute-based access)

🔹 3. Encryption (Protect data)

📦 What is Data In Transit?

Data is moving from one place to another

📦 What is Data At Rest?

Data is stored somewhere

Ex: Data in database, Files on disk

🔐 In transit (Network)

We protect data in transit using:

  • HTTPS / TLS
  • Prevents interception

🔐 At rest (Database)

We protect data in rest using:

  • Database encryption
  • Disk encryption

🔹 4. Network Security

  • Firewalls
  • VPC (Virtual Private Cloud)
  • Private subnets

Protects internal services from exposure.

🔹 5. API Security

  • API keys
  • Rate limiting
  • Input validation
  • Authentication tokens

🔹 6. Data Integrity

Ensure data is not modified illegally.

📝 Example:

  • Hashing (SHA-256)
  • Checksums

🔹 7. Data Protection

  • Mask sensitive data
  • Tokenization
  • Backup and recovery

4️⃣ Security Layers in System Design

🔹 1) Client Layer

  • Input validation
  • Secure cookies
  • Prevent XSS

🔹 2) Network Layer

  • HTTPS
  • Firewalls
  • Rate limiting

🔹 3) Application Layer

  • Authentication & Authorization
  • Input validation
  • Secure APIs

🔹 4) Database Layer

  • Encryption
  • Access control
  • Backup & recovery

5️⃣ Common Security Threats

Threat Example
SQL Injection Malicious DB queries
XSS Script injection
DDoS Overloading system
Man-in-the-middle Data interception

6️⃣ Input Validation

Input validation = checking user input before using it

🧩 Types of Input Validation

🔹 1. Format Validation

👉 Check structure

  • Email → abc@gmail.com
  • Phone → 10 digits

🔹 2. Range Validation

👉 Check limits

  • Age → 0 to 120
  • Price → > 0

🔹 3. Required Fields

👉 Ensure mandatory fields exist

Username cannot be empty

🔹 4. Type Validation

👉 Check data type

  • Age must be number
  • Name must be string

🔹 5. Length Validation

👉 Limit size

  • Password → min 8 chars
  • Comment → max 500 chars

7️⃣ What is XSS?

⚠️ XSS = Cross-Site Scripting

👉 It is an attack where:

  • Attacker injects malicious JavaScript into your website
  • That script runs in other users' browsers

✅ How to Prevent XSS

🔹 1. Escape Output (Most Important)

👉 Convert special characters:

<&script&>
👉 to :
&lt;script&gt;

👉 Now browser shows it as text, not code

8️⃣ Best Practices

  • Use HTTPS everywhere
  • Implement authentication + authorization
  • Encrypt sensitive data
  • Use rate limiting
  • Regular security audits
  • Follow least privilege principle

🎯 Summary

Security in system design involves protecting systems through authentication, authorization, encryption, and layered defenses to ensure data confidentiality, integrity, and availability.

🔥 Pro tip (Interview)

If asked:
👉 "How do you secure a system?"

Say:

Apply layered security: HTTPS for transport, authentication at entry, authorization in services, encryption at rest, and monitoring for threats.
